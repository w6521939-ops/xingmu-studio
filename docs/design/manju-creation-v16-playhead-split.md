# 成片页播放头拆分镜头 Design Spec

## 1. 来源与整体页面分析

- 视觉基准：`outputs/runtime/final-shot-batch-duplicate.png`、`outputs/runtime/final-shot-editing.png`、`outputs/runtime/storyboard.png`、`docs/design/manju-creation-v15-batch-duplicate.md`。
- 项目基准：Windows 桌面端 Electron + React + Vite 漫剧制作软件，简体中文、本地优先；剧本、图片、配音和视频 Provider 继续只预留接口，本轮不接入外部服务。
- 现状证据：成片时间线已经具备撤销、重做、恢复点、排序、调时长、多选、批量编辑、成组移动、安全删除和批量复制，但没有按播放头切割镜头的入口。
- 现有风险：分镜页的“拆分镜头”只新增一个固定 `2.0s`、无图片的后续镜头，原镜头时长不变，不能按成片播放位置拆分，也没有同步字幕、配音、音效和时间线历史。
- 参考画布：当前实测截图 `1777 × 974 px`；页面纵向滚动，镜头轨道横向滚动。
- 目标页面：项目内 `成片` 页的 `ProductionTimeline` 标题动作区与镜头轨道。
- 页面目的：把播放头所在的单个镜头切成前后两个连续镜头，保持项目总时长、画面连续性、配音进度、字幕显示、音轨位置和撤销重做正确。
- 页面类型：桌面创作工具中的直接、可逆剪辑动作；不新增页面、抽屉或确认弹窗。
- 视觉方向：沿用渐变天蓝、白色毛玻璃和深蓝文字；切刀属于安全创作动作，使用高辨识青蓝色，不使用删除红。
- 布局模型：`Header Flex + Track Relative Overlay + Fixed Snackbar`。
- 设计关键词：`sky-blue glassmorphism`、`precise playhead cut`、`non-destructive editing`、`visual continuity`、`single-step undo`。
- 间距系统：`4 / 6 / 8 / 12 / 16 / 24 px`。
- 圆角系统：图标按钮 `10 px`、文字按钮 `12 px`、镜头卡 `11 px`、提示条 `14 px`。
- 本轮主分类：成片时间线镜头拆分；副分类：配音/字幕连续性、动效范围和可逆历史。
- 本轮边界：只做播放头处单镜头拆分；不做常驻刀片模式、自由切多轨、波形切割、自动语义断句、源音频文件改写、跨项目剪贴板、素材去重或外部接口接入。

## 2. 核心产品决策

### 2.1 拆分触发与有效范围

- 用户把播放头移动到目标镜头内部，点击标题栏 `拆分镜头` 或按 `Ctrl+B`。
- 播放头必须让左右片段都至少保留 `0.5 秒`；目标镜头不足 `1.0 秒`时不可拆分。
- 播放头位于镜头起点、终点或距边界不足 `0.5 秒`时不提交，提示：`请将播放头移到镜头内部，左右至少保留 0.5 秒。`
- 多选模式下禁用拆分，避免“拆分哪个镜头”的歧义；退出多选后按当前播放头判断目标。
- 导出中、拖动排序中、拉伸时长中、批量复制提交中或删除恢复点建立中禁用拆分。
- 拆分为直接可逆操作，不弹确认框；成功后可通过 Snackbar、`Ctrl+Z`、操作历史和恢复点撤销。

### 2.2 镜头集合与时长

- 左片段保留原镜头 ID 和原时间线位置。
- 右片段生成全局唯一数值镜头 ID，紧跟左片段插入。
- 左时长为 `播放头 - 原镜头起点`，右时长为 `原镜头终点 - 播放头`，统一保留 `0.1 秒`精度。
- 左右时长之和必须严格等于原镜头时长；后续镜头起点、项目总时长、BGM 和自由字幕绝对时间不变。
- 右片段完整深克隆剧集、场景、画面、动作、台词、景别、运镜、提示词、角色绑定、服装、连续性和图片状态。
- 右片段记录兼容字段 `draftSource: "split"` 和 `splitSourceShotId`；不提升 `.manju` 项目格式版本。
- 图片 Data URL 在两个镜头对象中都会出现，因此提交前继续执行完整候选项目的 `10 MB` UTF-8 序列化体积预检。

### 2.3 画面运动与转场连续性

- 不能让拆分后的两段重新从动效起点播放，否则推近、拉远和平移会在切点跳变。
- 为镜头增加可选的归一化动效范围：`motionRangeStart`、`motionRangeEnd`，默认分别为 `0`、`1`。
- 若原镜头动效范围为 `[start, end]`，切点比例为 `ratio`：
  - 左片段范围为 `[start, start + (end - start) × ratio]`。
  - 右片段范围为 `[start + (end - start) × ratio, end]`。
- 成片预览和 FFmpeg 导出都必须按该范围计算运动进度，切点前后画面位置保持连续。
- 现有 `transition` 默认表示镜头首尾都使用同一种过渡；拆分后需要可选边界覆盖：
  - 左片段：保留原入场过渡，内部切点出场为 `cut`。
  - 右片段：内部切点入场为 `cut`，保留原出场过渡。
- 使用兼容字段 `transitionIn`、`transitionOut` 表达边界覆盖；旧项目缺失时继续由原 `transition` 同时控制首尾。
- 用户随后在镜头动效区手动更改转场时，当前镜头的 `transitionIn` 和 `transitionOut` 同步重置为新值，避免旧拆分覆盖继续隐藏生效。

### 2.4 角色配音连续性

- 源 `lines` 台词记录不复制，右片段复用左片段已经匹配的同一台词音频。
- 左片段从原音频偏移开始播放，并在左片段结束处截断；右片段从切点对应的音频偏移继续播放，不得从头重复。
- 使用兼容字段 `voiceSourceShotId` 和 `voiceOffsetSeconds`：
  - 左片段沿用原偏移，旧项目默认 `0`。
  - 右片段偏移为 `原偏移 + 左片段时长`。
- 预览播放器进入右片段时，将音频 `currentTime` 设置为 `voiceOffsetSeconds + 当前片段内偏移`。
- FFmpeg 导出时对右片段角色配音使用相同偏移截取；若音频短于所需区间，则沿用现有静音补齐，不循环、不报错中断。
- 同一源台词仍只保存一份音频 Data URL；右片段只通过来源镜头和偏移引用，不复制 `lines`。

### 2.5 字幕、SFX 与 BGM

- 项目总时长和原切点后的绝对时间不变，因此自由字幕、SFX 和 BGM 不做整体重映射。
- 无 `sourceItemId` 的自由字幕保持原绝对起止时间，不复制、不拆分。
- 绑定原镜头且完全位于切点左侧的字幕继续绑定左片段。
- 绑定原镜头且完全位于切点右侧的字幕改绑右片段稳定时间线 ID，绝对时间不变。
- 绑定原镜头且跨越切点的字幕拆成两个相邻 cue：左 cue 保留原 ID，右 cue 生成唯一 ID并绑定右片段；两段文字相同且时间首尾相接，使画面上保持连续显示而不闪烁。
- SFX 和 BGM 不复制，起点与全部参数保持绝对值；切点只改变 SFX 所属镜头判断，不改变声音播放结果。
- 如果后续删除任一片段，V14 删除规则继续按当前时间线处理相应字幕和 SFX。

### 2.6 焦点、历史和体积保护

- 成功后右片段成为 `selectedShot`，播放头保持在原切点，用户可以立即编辑后半段。
- 多选模式保持关闭，不自动选择两个片段。
- 一次拆分只记录一步历史：`拆分镜头 03`。
- 复用 V14/V15 权威镜头集合快照：拆分前快照设置 `shotSetAuthoritative: true`，并在 `restorableShots` 中保存完整右片段对象。
- 撤销时移除右片段并恢复原镜头完整时长、动效范围、转场边界、字幕、音轨、播放头和焦点。
- 重做时恢复同一右片段 ID、图片、提示词、角色绑定、配音偏移、字幕来源和动效连续性。
- 提交前构造完整候选项目快照；超过 `10 MB` 时不修改镜头、字幕、音轨、历史或恢复点，提示：`拆分后项目将超过 10 MB，请先移除部分图片或音频。`
- 成功后触发现有 `.manju` 自动保存和恢复点防抖，不新增 IPC、权限或存储目录。

## 6. 交互流程

```text
移动播放头到镜头内部
  -> 校验当前不是多选、导出或拖动状态
  -> 校验左右片段均不少于 0.5 秒
  -> 构造左片段与完整右片段
  -> 切分动效范围、转场边界、配音偏移和绑定字幕
  -> 保持自由字幕、SFX、BGM 与总时长不变
  -> 构造完整候选项目并计算 UTF-8 体积
      -> 超过 10 MB：停止并显示体积错误
      -> 未超过：记录一个权威历史事务
          -> 一次性提交镜头、字幕、播放头和焦点
          -> 右片段成为主镜头
          -> 显示 8 秒撤销 Snackbar
          -> 触发现有自动保存与恢复点防抖
```

### 6.1 鼠标与键盘

- 点击 `拆分镜头` 与非表单焦点下的 `Ctrl+B` 等价。
- 焦点位于 `input`、`textarea`、`select` 或可编辑区域时不响应 `Ctrl+B`，保留文本加粗等编辑行为。
- 快捷键触发成功时阻止浏览器默认行为。
- 连续快速触发使用提交后的当前右片段和播放头；由于播放头位于新右片段起点，第二次会因距边界不足 `0.5 秒`而被安全拒绝，不生成零长度镜头。
- 拆分按钮 hover 或键盘聚焦时增强 `PlayheadCutGuide`，让用户在提交前看清切点。

### 6.2 播放、试听与焦点

- 成功提交前停止连续播放、角色配音预览和独立音轨试听，避免旧时间线播放器继续发声。
- 提交后播放头保持原绝对时间，不自动播放。
- 右片段成为主镜头；焦点仍留在拆分按钮，Snackbar 不抢焦点。
- 撤销后恢复原镜头为主镜头；重做后再次聚焦右片段，但不重复显示 Snackbar。

## 7. 数据与服务层映射

| 设计区域 | 建议映射 | 责任边界 |
| --- | --- | --- |
| 拆分按钮与快捷键 | `FinalPage` 标题动作区与全局时间线快捷键 | 读取当前播放头、管理短生命周期提交状态和反馈 |
| 镜头拆分 | `shotTimelineEditService.js` 新增纯函数 | 校验边界、生成唯一 ID、切时长和构造最终镜头顺序 |
| 字幕切分 | `shotTimelineEditService.js` | 只处理绑定原镜头的 cue；自由字幕保持绝对时间 |
| 配音连续性 | `timelineService.js`、预览播放逻辑、`videoExportService.js` | 复用同一 line，按 `voiceOffsetSeconds` 续播和截取 |
| 动效连续性 | `shotMotionService.js`、`videoExportService.js` | 用 `motionRangeStart/End` 映射预览与 FFmpeg 进度 |
| 转场边界 | `shotMotionService.js`、`videoExportService.js` | 支持 `transitionIn/Out`，旧项目回退到 `transition` |
| 项目体积预检 | 复用 `projectModel.js` 的字节计算 helper | 只判断完整候选快照，不读写文件 |
| 历史事务 | 复用 `timelineHistoryService.js` 权威集合快照 | 一步撤销/重做完整右片段和原镜头参数 |
| 自动保存 | 现有项目 Repository | 不新增 IPC、schema 版本、权限或外部服务 |
| 样式 | `App.css` | 标题按钮、切点导线和拆分 Snackbar |

## 8. 状态、异常与响应式

- `idle-valid`：播放头处于有效切点，按钮启用，显示青蓝切点导线。
- `idle-invalid`：播放头距边界不足 `0.5 秒`或镜头不足 `1.0 秒`，按钮禁用。
- `splitting`：同步计算期间禁用拆分、复制、删除、批量应用、拖动和拉伸，防止重复事务。
- `success`：右片段成为主镜头，播放头保持切点，显示撤销 Snackbar。
- `size-error`：超过 10 MB；全部项目数据与历史保持不变。
- `multi-select`：拆分按钮禁用；title 为 `退出多选后可拆分播放头所在镜头`。
- `empty`：无镜头时按钮禁用，轨道继续显示现有空态。
- `undo`：恢复原镜头、原时长、原动效范围、原字幕和原焦点。
- `redo`：恢复相同右片段 ID及全部连续性字段，不重新做体积预检。
- `long text`：按钮保持短文案；Snackbar 最多两行；镜头动作和台词不进入提示条。
- `small screen`：小于 `1180 px` 时标题动作区换行，拆分按钮与撤销/重做保持同组；小于 `760 px` 时 Snackbar 距边 `14 px`、宽 `calc(100vw - 28px)`。
- `150% Windows scaling`：按钮允许增长到 `126 px`，文案不省略关键动词；切线保持至少 `1 CSS px`。
- `dark mode`：当前不新增全局暗色主题；高对比模式使用边框、图标和文字共同表达启用状态。
- `orientation`：编辑器仍以桌面横向为基准；导出 9:16/16:9 不改变工具条布局。
- `safe area`：Windows 桌面无移动端安全区；固定 Snackbar 不覆盖窗口滚动条。
- `reduced motion`：取消导线透明度过渡和 Snackbar 位移，直接显示。
- `permission denied`：不新增文件、麦克风、相机或网络权限。

## 13. 不确定项与设计假设

- 将“下一步”解释为继续补齐专业成片时间线的核心编辑动作；在现有排序、调时长、批量编辑、移动、删除和复制之后，播放头拆分是最明显的能力缺口。
- V16 定义的是成片时间线视觉切割，不替代分镜页的内容创作拆分；后续可单独重构分镜页旧按钮的动作/台词语义拆分。
- 配音连续性按镜头时间偏移续播，不做语音识别或字级对齐；这能保持声音不重复，但不会自动把句子语义精确分配到左右镜头。
- 自由字幕和音效已经使用绝对时间，项目总时长不变时不应重映射；只处理绑定原镜头的字幕来源。
- 图片 Data URL 仍按真实项目字节重复计入候选体积；本轮不引入素材去重仓库或文件引用 schema。
- 新兼容字段均为可选字段，旧 `.manju` 不迁移版本也能继续读取；实际实现必须为缺失字段提供明确默认值。
- V16 不接入 AI、云端、付费或第三方 Provider，不增加依赖、权限或新 IPC。
