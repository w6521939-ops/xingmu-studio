# 成片页安全批量删除 Design Spec

## 1. 来源与整体页面分析

- 视觉基准：`outputs/runtime/final-shot-group-reorder.png`、`docs/design/manju-creation-v12-shot-multiselect-batch-edit.md`、`docs/design/manju-creation-v13-group-reorder.md`。
- 项目基准：Windows 桌面端 Electron + React + Vite 漫剧制作软件，简体中文界面，本地优先；外部剧本、图片、配音和视频 Provider 继续只预留接口，本轮不接入。
- 参考画布：实际运行截图 `1777 × 974 px`；页面纵向滚动，镜头轨道可横向滚动。
- 目标页面：项目内 `成片` 页的 `ProductionTimeline`，扩展现有多选工具栏、时间线历史和恢复点能力。
- 页面目的：允许用户一次删除一个或多个镜头，同时明确说明删除会影响项目分镜和成片时间线，并保证可以撤销、重做或从删除前本地恢复点找回。
- 页面类型：桌面生产工具中的高风险批量操作确认流程；布局为 `Grid + Flex + Fixed Modal + Fixed Snackbar` 混合结构。
- 视觉方向：继续天蓝渐变、白色毛玻璃、深蓝文字；危险操作只在按钮、警告图标和确认动作中使用低饱和珊瑚红，不把整页改成红色警报界面。
- 设计关键词：`Sky-blue glassmorphism`、`safe destructive action`、`clear consequence preview`、`local recovery`、`single-layer timeline`。
- 间距系统：沿用 `4 / 8 / 12 / 16 / 24 px`。
- 圆角系统：紧凑按钮 `9 px`、信息块 `12 px`、确认弹窗 `20 px`、恢复提示条 `14 px`。
- 阴影：常规玻璃卡片使用冷蓝阴影；确认弹窗使用 `0 28px 80px rgba(25,87,125,.28)`，不使用纯黑重阴影。
- 图标：沿用现有线性 SVG 图标；删除使用垃圾桶语义，恢复使用逆时针箭头，警告使用圆角三角形。
- 本轮主分类：时间线数据删除；副分类：历史恢复与危险操作 UX。
- 本轮边界：只做镜头安全删除；不做批量复制、跨项目移动、回收站页面、持久分组、片段嵌套、磁性吸附、关键帧或外部接口接入。

## 5. 删除交互流程

```text
选择 1 个或多个镜头
  -> 点击“删除所选”或按 Delete / Backspace
  -> 打开 SafeDeleteModal
  -> 展示删除规模、缩短时长、关联字幕和 SFX 数量
  -> 用户取消：关闭弹窗，不改变任何数据
  -> 用户确认：按钮进入“建立恢复点…”
      -> 恢复点失败：保持弹窗，显示错误和重试，不删除
      -> 恢复点成功：记录单步历史并一次性提交删除
          -> 重建时间线与关联字幕/SFX
          -> 退出多选并聚焦最近的保留镜头
          -> 显示 8 秒撤销 Snackbar
          -> 自动保存新的 .manju 状态
```

### 5.1 选择与焦点

- 删除支持 `1–N` 个镜头；批量参数应用仍要求至少 2 个，二者规则分离。
- 打开弹窗时冻结当前有效选择 ID，后续统计和确认均基于该快照，避免弹窗打开期间集合漂移。
- 删除完成后退出多选并清空选择集合，避免撤销后立即再次误删。
- 主镜头被删除时，优先聚焦第一个删除位置之后的保留镜头；不存在时聚焦前一个保留镜头；全部删除时聚焦 ID 为 `0`。
- `Delete` / `Backspace` 仅在焦点不位于 `input`、`textarea`、`select` 或可编辑文本时生效。

### 5.2 全选删除

- 允许删除全部镜头，但必须使用更明确的标题、文案和按钮：`删除全部 N 个镜头？` / `删除全部镜头`。
- 弹窗明确提示成片时间线将为空、导出会停用、源台词和角色仍保留。
- 删除后：`shots=[]`、字幕清空、SFX 清空、BGM 保留并将起点规范为 `0`、播放头归零。
- 用户可通过 Snackbar、`Ctrl+Z`、操作历史或删除前恢复点恢复全部镜头。

## 6. 数据删除与时间线映射规则

### 6.1 镜头数据

- 删除作用于项目级 `shots` 集合，不是仅从成片轨道隐藏；分镜页会同步移除这些镜头。
- 删除保留剧集、场景、角色和 `lines` 源台词；角色配音源数据继续保存在台词记录中。
- 每个被删镜头的完整字段都要进入可撤销备份，包括图片 Data URL、画面提示词、动作、台词、角色绑定、服装、连续性、动效和转场。
- 删除顺序以当前时间线中的稳定镜头 ID 为准，不依赖用户勾选先后。

### 6.2 字幕

- `sourceItemId` 指向被删镜头的绑定字幕随镜头删除，并计入弹窗“关联字幕”数量。
- 无来源字幕完全落在被删时间段内时删除；完全位于保留镜头中的字幕随保留镜头的新起点重映射。
- 无来源字幕跨越删除边界时压缩被删区间并保留剩余可见部分；结果短于 `0.1 秒` 时删除。
- 保留字幕的 ID、文字和样式不变；删除后统一排序并限制在新总时长内。
- 全部镜头删除时字幕列表清空，但全局字幕样式仍保留。

### 6.3 音频

- 角色配音不作为独立删除对象；保留镜头会继续从 `lines` 匹配配音，被删镜头不再进入成片混音。
- SFX 起点落在被删镜头内时随镜头删除，并计入弹窗“时间线音效”数量。
- SFX 位于保留镜头内时保持该镜头内的相对偏移，并映射到新起点。
- BGM 始终保留绝对起点；新总时长缩短后只做合法范围裁剪，不随前方镜头删除整体左移。
- 全部镜头删除时保留 BGM 文件与音量/淡入淡出设置，起点归零；全部 SFX 清空。

### 6.4 播放头与预览

- 播放头位于保留镜头时保持镜头内相对进度。
- 播放头位于被删镜头时跳到下一个保留镜头的新起点；没有下一个时跳到上一个保留镜头的末尾；没有任何镜头时归零。
- 删除确认前停止播放、角色配音预览和独立音轨试听，避免数据提交后旧播放器继续发声。
- 总时长、进度条、成片预览、就绪统计和 FFmpeg 导出均使用删除后的新时间线。

## 7. 历史、撤销与恢复点设计

### 7.1 现状风险

- 当前时间线历史只保存镜头 ID、时长、动效与转场；普通重排和改时长足够，但删除后当前 `shots` 中已没有完整镜头对象。
- 如果只复用现有快照，撤销删除无法找回图片、提示词、角色绑定和连续性数据；因此 V14 必须扩展删除事务快照，不能只在页面中 `filter`。

### 7.2 删除事务快照

- 普通时间线编辑继续使用轻量 `shotTimeline`，不复制所有镜头图片，避免 40 步历史因 Data URL 急剧膨胀。
- 仅删除事务额外保存：
  - `shotSetAuthoritative: true`：该快照的镜头 ID 集合为需要精确恢复的项目集合。
  - `restorableShots`：只保存本次将被删除镜头的完整对象。
  - `focusedShotId`：撤销后应恢复的主镜头。
- 删除前快照包含完整被删镜头；删除后的重做快照只需要权威剩余 ID，不重复保存图片数据。
- 应用普通快照时继续保留快照外的新镜头；只有 `shotSetAuthoritative` 为真时才按权威 ID 精确增删，避免撤销普通动效时误删用户后来新增的镜头。
- 一次删除只记录一步：`删除 3 个镜头`；撤销和重做同时恢复/移除镜头、字幕、SFX、BGM 状态、播放头和主镜头。
- 多选集合不写入历史或 `.manju`；撤销删除后不自动重新多选，降低二次误删风险。

### 7.3 删除前恢复点

- 用户确认后先调用现有本地恢复点 Repository 保存完整项目快照，不新增 IPC、权限或外部服务。
- 恢复点成功后才执行删除；失败时不改变项目数据，并在弹窗内提供重试。
- 删除后的常规自动恢复点继续按现有防抖逻辑建立，形成“删除前”和“删除后”两个可追溯状态。
- 恢复点仍按项目隔离、最多保留 8 个；不得上传图片、音频、项目文本或恢复数据。

## 9. 状态与异常处理

- `idle`：删除按钮按有效选择显示数量语义。
- `modal-open`：冻结选择，停止播放；页面其他交互不可点击。
- `saving-recovery`：确认按钮显示进度并禁用取消、遮罩关闭和重复提交。
- `recovery-error`：镜头未删除；显示错误和重试，`Escape` 仍可安全退出。
- `committing`：同步计算并一次性更新；期间禁用时间线拖动、时长拉伸和导出。
- `success`：关闭弹窗、退出多选、显示 8 秒撤销 Snackbar。
- `undo`：恢复完整镜头与关联时间线数据；Snackbar 消失，重做按钮可用。
- `redo`：重新删除同一集合，不再次弹窗，但继续形成操作历史记录。
- `empty`：全部删除后显示空时间线、禁用导出和播放。
- `no-op`：确认前镜头集合发生变化导致没有有效目标时关闭弹窗并通知，不记录历史。
- `long text`：弹窗不显示镜头标题列表，只显示数量和影响摘要，避免长标题撑破布局。
- `small screen`：小于 `760 px` 宽时弹窗改为左右 `16 px` 边距，统计块纵向排列；批量工具栏允许两行换行。
- `high contrast`：危险按钮和确认按钮必须保留边框、文字和图标三重语义，不只依赖红色。
- `dark mode`：当前项目没有完整暗色主题；局部确认层必须保持文字对比度，不做简单颜色反转。
- `permission denied`：不新增权限；本地恢复点写入失败按 `recovery-error` 处理。

## 10. 动效规范

- 删除弹窗：遮罩 `140 ms` 淡入；卡片 `160 ms` 从 `translateY(8px)` 过渡到原位。
- 危险按钮：悬停只改变边框和背景，不脉冲、不抖动。
- 恢复点进度：`1.1 s` 细线旋转；不遮挡按钮文案。
- 删除成功：镜头直接提交最终结果，不逐张飞出；避免数据已删除但动画仍显示旧顺序。
- Snackbar：`160 ms` 淡入并右移归位，8 秒后 `120 ms` 淡出。
- `prefers-reduced-motion`：取消位移、旋转以静态状态图标替代，保留颜色和文案变化。

## 15. 不确定项与设计假设

- 当前没有独立回收站页面；V14 以“删除前恢复点 + 操作历史 + 8 秒撤销 Snackbar”提供三层恢复，不新增回收站导航。
- 当前历史快照不足以恢复已删除镜头完整对象；V14 需要删除专用轻量扩展，而不是把所有镜头图片复制进每一步普通历史。
- SFX 目前没有显式镜头 ID 绑定，因此以开始时间所在镜头判断归属；V14 不改变 `.manju` 音轨 schema。
- 自由字幕跨越删除区间时采用压缩映射，不自动拆成多条字幕；如果剩余有效长度不足 `0.1 秒` 则移除。
- 全选删除被允许，因为已有确认、撤销和恢复点；源台词、角色、剧集与场景不会随镜头删除。
- 危险色只服务于删除动作，主界面仍以用户确认的渐变天蓝色毛玻璃为主。
- V14 不接入任何 AI、云端、付费或第三方 Provider，也不增加权限、依赖或新 IPC。
