# 成片页批量复制镜头 Design Spec

## 1. 来源与整体页面分析

- 视觉基准：`outputs/runtime/final-shot-batch-editing.png`、`outputs/runtime/final-shot-safe-delete.png`、`docs/design/manju-creation-v12-shot-multiselect-batch-edit.md`、`docs/design/manju-creation-v13-group-reorder.md`、`docs/design/manju-creation-v14-safe-batch-delete.md`。
- 项目基准：Windows 桌面端 Electron + React + Vite 漫剧制作软件，简体中文、本地优先；剧本、图片、配音和视频 Provider 继续只预留接口，本轮不接入外部服务。
- 参考画布：当前实测截图 `1777 × 974 px`；页面纵向滚动，镜头轨道横向滚动。
- 目标页面：项目内 `成片` 页的 `ProductionTimeline`，扩展现有多选操作组、时间线历史与恢复点能力。
- 页面目的：允许用户复制一个、连续多个或非连续多个镜头，完整保留镜头图片、提示词、角色绑定、连续性、动效与转场，并同步复制所属字幕和时间线音效。
- 页面类型：桌面创作工具中的可逆批量操作；布局继续使用 `Grid + Flex + Fixed Snackbar`，不新增页面、抽屉或确认弹窗。
- 视觉方向：沿用天蓝渐变、白色毛玻璃、深蓝文字；复制属于安全创作动作，使用青蓝图标与描边，与 V14 珊瑚色危险删除形成清晰区分。
- 设计关键词：`sky-blue glassmorphism`、`reversible batch action`、`predictable insertion`、`local-first continuity`、`single-layer timeline`。
- 间距系统：`4 / 6 / 8 / 12 / 16 / 24 px`。
- 圆角系统：紧凑按钮 `9 px`、镜头卡 `11 px`、提示条 `14 px`。
- 本轮主分类：时间线镜头复制；副分类：字幕/音效复制、撤销重做与项目体积保护。
- 本轮边界：只做同一项目内的镜头复制；不做系统剪贴板、跨项目粘贴、跨窗口拖放、持久分组、素材去重、关键帧或外部接口接入。

## 2. 核心产品决策

### 2.1 插入位置

- 所有副本按原时间线中的相对顺序组成一个连续组。
- 副本组插入到“最后一个所选原镜头”之后，而不是分别插入每个原镜头后面。
- 例：`[A, B, C, D, E]` 选择 `[B, D]` 后复制，结果为 `[A, B, C, D, B', D', E]`。
- 全选后复制时，副本组追加在时间线末尾。
- 单选复制也使用同一规则，相当于把副本插到原镜头后。
- 该规则与 V13 成组移动一致：复制完成后新副本保持选中，可直接拖动整组到目标位置。

### 2.2 复制范围

- 完整复制镜头字段：剧集、场景、画面、动作、台词、时长、景别、运镜、画面提示词、角色绑定、服装、连续性、图片状态、图片 Data URL、动效、强度、转场与转场时长。
- 为每个副本生成全局唯一镜头 ID；不得复用原 ID。
- `lines` 源台词、角色、剧集和场景不复制；副本镜头继续引用同一业务上下文，角色配音可沿用现有台词匹配逻辑。
- 绑定字幕随所属镜头复制，并改写到副本镜头的稳定时间线 ID。
- 完全落在所选镜头内部的自由字幕随该镜头复制；跨越镜头边界的自由字幕只保留原件，不自动拆分。
- 起点落在所选镜头内部的 SFX 按镜头内相对偏移复制；BGM 不复制，绝对起点不变。

### 2.3 可逆性与体积保护

- 复制不弹确认框，点击后直接提交，因为操作可通过 Snackbar、`Ctrl+Z`、操作历史和恢复点撤销。
- 提交前使用当前完整项目快照估算复制后的 UTF-8 序列化体积；超过既有 `10 MB` `.manju` 上限时阻止复制。
- 阻止时不新增镜头、不写历史、不建立恢复点，提示：`复制后项目将超过 10 MB，请先移除部分图片或音频。`
- 不为解决体积问题引入新素材仓库、文件引用或 schema 版本；保持现有 `.manju` 兼容。

## 6. 复制交互流程

```text
选择 1 个或多个镜头
  -> 点击“复制所选”或按 Ctrl+D
  -> 冻结当前有效选择 ID
  -> 生成副本镜头与唯一 ID
  -> 生成绑定字幕、镜头内自由字幕和 SFX 副本
  -> 构造最终时间线并估算完整项目序列化体积
      -> 超过 10 MB：停止，显示体积错误，数据保持不变
      -> 未超过 10 MB：记录一个权威历史事务
          -> 一次性提交镜头、字幕、音轨和播放头
          -> 原选择切换为新副本组
          -> 第一个副本成为主镜头
          -> 显示 8 秒撤销 Snackbar
          -> 触发现有自动保存与恢复点防抖
```

### 6.1 鼠标与键盘

- `复制所选` 支持 `1–N` 个镜头；不要求至少 2 个。
- 非表单焦点且多选模式开启时，`Ctrl+D` / `Cmd+D` 等价于点击复制按钮，并阻止浏览器默认收藏行为。
- 焦点位于 `input`、`textarea`、`select` 或可编辑区域时不响应 `Ctrl+D`，保留文本编辑行为。
- 连续快速点击必须以每次提交后的当前选择为准：第二次复制复制的是上一轮新副本，而不是重复使用过期 ID。
- 导出中、指针拖动中、时长拉伸中或删除恢复点保存中禁止复制。

### 6.2 焦点、选择和播放头

- 复制提交后保持多选模式，`selectedShotIds` 替换为所有新副本 ID。
- 第一个副本设为 `selectedShot` 与范围选择锚点。
- 播放头跳到第一个副本的新起点；若复制前播放头位于主镜头内，可保留该镜头内相对偏移，但不得超出副本时长。
- 复制前停止连续播放、角色配音预览和独立音轨试听，避免旧时间线播放器继续发声。
- 撤销复制后回到复制前镜头集合和播放头；不自动恢复旧批量选择，避免再次误操作。

## 7. 数据与时间线映射规则

### 7.1 镜头与 ID

- 目标顺序由当前 `shots` 时间线决定，忽略用户勾选先后。
- 新 ID 从当前项目最大数值镜头 ID 后顺序分配；一次批量复制内不得冲突。
- 副本使用深克隆的可编辑数组字段，例如 `characterIds`；图片和音频 Data URL 内容保持一致，但项目序列化时按真实字节计入体积。
- 可增加已有兼容字段 `draftSource: "duplicate"` 作为来源标记；不依赖该字段驱动 UI，不提升项目格式版本。
- 实现时同时记录兼容字段 `duplicateSourceShotId`，让副本精确复用来源镜头已匹配的台词音频，避免抢占后续原镜头的未使用台词；重复复制时该字段指向本轮直接来源镜头。

### 7.2 字幕

- 有 `sourceItemId` 且指向所选镜头的字幕复制一份，新 `sourceItemId` 指向对应副本镜头。
- 字幕副本保留文字、样式语义和镜头内起止偏移，并生成唯一字幕 ID。
- 完全落在某个所选镜头内的自由字幕复制到对应副本的相同局部时间。
- 跨镜头边界、跨选中与未选中区域的自由字幕不复制，原字幕按最终时间线同步到原内容位置。
- 原有字幕和新副本字幕统一排序、限制在最终总时长内，最短有效时长继续为 `0.1 秒`。

### 7.3 音频

- 角色配音由副本镜头的剧集、场景和台词继续匹配原 `lines` 音频，不复制源台词记录。
- 起点落在所选镜头内部的 SFX 复制到对应副本，保留镜头内相对偏移、名称、音频、波形、音量、淡入淡出和时长，并生成唯一音轨 ID。
- 跨越镜头边界的 SFX 以起点所在镜头决定归属；本轮不自动切割音频。
- BGM 不复制，起点保持绝对值；最终总时长增加后不自动延长音频文件，只按现有循环/导出规则使用。
- 原 SFX 与 BGM 先按原镜头最终新位置同步一次，再追加副本 SFX，避免多轮累计误差。
- 现有“最多导入 6 条音轨”限制只约束手动导入入口；镜头复制产生的 SFX 副本会完整保存和回读，不能在项目加载时静默截断。

### 7.4 历史、撤销和恢复

- 一次复制只记录一步历史：`复制 3 个镜头`。
- 复用 V14 权威镜头集合快照：复制前快照使用 `shotSetAuthoritative: true`，并在事务元数据保存完整副本镜头作为 `restorableShots`。
- 撤销时精确移除副本，恢复原字幕、音轨、播放头和主镜头；重做时使用完整副本对象恢复图片、提示词、角色绑定和连续性。
- 普通时长、动效或排序历史继续使用轻量快照，不把所有图片 Data URL 写入每一步。
- 复制后复用现有自动恢复点与 `.manju` 自动保存；复制前不额外强制建立恢复点，因为操作不破坏原镜头且可撤销。
- 不保存多选集合到历史、恢复点或 `.manju`。

## 8. 状态、异常与响应式

- `idle`：按钮根据有效选择启用。
- `duplicating`：同步计算期间禁用复制、删除、应用批量参数和拖动；防止双击重复事务。
- `success`：副本组被选中，播放头定位，显示撤销 Snackbar。
- `size-error`：超过 10 MB；原数据与历史完全不变，显示错误通知。
- `no-op`：选择 ID 已失效或无有效目标时不提交，通知 `所选镜头已发生变化，没有执行复制。`
- `undo`：删除全部副本并恢复原时间线；Snackbar 关闭，重做可用。
- `redo`：恢复同一批副本与关联字幕/SFX，不再次提示体积错误。
- `empty`：无镜头时多选和复制按钮均禁用，不渲染批量栏。
- `disabled`：导出中、拖动中、拉伸中、删除恢复点保存中不可复制。
- `pressed`：按钮下移 `1 px`，不改变布局宽度。
- `selected`：副本使用勾选框、内描边和主镜头外环三重语义。
- `permission denied`：不新增权限、文件选择或系统弹窗。
- `long text`：按钮只显示短文案；Snackbar 最多两行；不显示镜头标题列表。
- `small screen`：小于 `1180 px` 时批量栏多行布局，操作组整体占一行；小于 `760 px` 时 Snackbar 距边 `14 px`、宽 `calc(100vw - 28px)`。
- `dark mode`：当前不新增全局暗色主题；高对比模式下按钮保留图标、边框和文字，不只靠颜色区分。
- `orientation`：编辑器仍以桌面横向为基准；导出 9:16/16:9 不改变工具条布局。
- `safe area`：Windows 桌面无移动端安全区；固定提示条不得覆盖页面滚动条和系统窗口边缘。
- `reduced motion`：取消滚动动画与 Snackbar 位移，直接定位和淡入。

| 字幕/SFX 复制 | `shotTimelineEditService.js` | 基于旧时间线和最终时间线一次映射，生成唯一字幕/音轨 ID |
| 项目体积预检 | 独立纯函数或项目模型 helper | 以完整候选快照的 UTF-8 字节数对照现有 10 MB 上限，不读写文件 |
| 历史事务 | 复用 `timelineHistoryService.js` 的权威集合元数据 | 一步撤销/重做完整镜头集合，不让普通历史膨胀 |
| 保存与恢复 | 现有项目 Repository | 自动保存与恢复点，不新增 IPC 或 schema |
| Snackbar | 复用/泛化现有 V14 可撤销提示组件 | 展示结果与撤销动作，不管理业务数据 |
| 样式 | `App.css` 的批量操作组和提示条 | 增加安全复制按钮与响应式宽度，保持现有天蓝毛玻璃 |

## 14. 不确定项与设计假设

- “副本组插入最后一个所选原镜头之后”是根据当前成组移动模型推导的默认行为；它比逐个紧邻插入更利于继续成组操作。
- 当前项目把图片和音频嵌入 `.manju`；复制会真实增加序列化体积，因此设计为提交前做 10 MB 预检，不假装素材已去重。
- 自由字幕跨镜头时不复制，避免隐式拆分改变语义；原字幕仍按最终时间线同步。
- SFX 没有显式镜头 ID，继续用起点所在镜头判断归属；本轮不升级音轨 schema。
- 复制后只选中新副本，不同时选中原件；这使后续成组移动、再次复制和批量调整更加明确。
- V15 不接入 AI、云端、付费或第三方 Provider，不增加依赖、权限、IPC 或项目格式版本。
