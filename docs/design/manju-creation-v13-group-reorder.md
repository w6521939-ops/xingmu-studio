# 成片页多选镜头成组重排 Design Spec

## 1. 来源与整体分析

- 视觉基准：`outputs/runtime/final-shot-batch-editing.png`、`docs/design/manju-creation-v11-shot-reorder-duration-sync.md`、`docs/design/manju-creation-v12-shot-multiselect-batch-edit.md`。
- 参考画布：Windows 桌面横向窗口，运行截图 `1777 × 974 px`；页面纵向滚动，镜头轨道可横向滚动。
- 目标页面：项目内 `成片` 页的 `ProductionTimeline`；扩展 V12 多选镜头在现有 `ShotTrack` 内的拖动语义。
- 产品目标：用户选中多个镜头后，只需拖动任一已选镜头的握把，即可将整组镜头移动到新位置；组内保持原顺序，字幕、角色配音、SFX 和播放头同步更新。
- 视觉方向：继续渐变天蓝色、白色毛玻璃、深蓝文字和单层时间线；用组拖动徽标、统一淡化和增强插入线表达“正在移动 N 个镜头”，不引入浮动专业剪辑工具箱。
- 本轮边界：只做成组重排与键盘替代操作；不做批量删除、持久分组、磁性吸附、片段嵌套、跨项目复制或关键帧。
- 本轮主分类：时间线交互；副分类：批量数据同步与历史恢复。

## 2. 页面结构拆解

```text
FinalPage
└── ProductionTimeline
    ├── TimelineHeader
    ├── TimelineSafetyPanel（可选）
    ├── BatchEditBar（多选模式）
    │   └── SelectionSummary
    │       └── GroupMoveHint
    └── ShotTrack
        ├── GroupDropIndicator（组拖动时可见）
        ├── GroupDragBadge（组拖动时可见）
        └── ShotSegment
            ├── ShotSelectionControl
            ├── ShotDragGrip
            ├── ShotSelectSurface
            └── ShotDurationHandle
```

## 3. 组件级设计稿

| 文案 | 选中 2 个以上且未全选时：`可成组拖动`；全选时：`全部已选，顺序不变` |
| 字体 | `8 px / 12 px / 550`，颜色 `#6C8A9B` |
| 图标 | `10 × 10 px` 的水平移动箭头；资源缺失时只显示文字 |
| 长文本 | Windows 150% 文本缩放时允许换行，不覆盖数量徽标 |

### 3.2 GroupDragBadge

| 字段 | 规格 |
| --- | --- |
| 类型 | Floating Drag Status Badge |

| 文案 | 主文案 `移动 3 个镜头`；辅助文案 `合计 8.5 秒` |
| 图标 | 三层叠放镜头卡，`16 × 16 px`；占徽标高度约 `47%`；缺失时用 CSS 圆角矩形叠层 |
| 字体 | 主文案 `10 px / 14 px / 750`；辅助文案 `8 px / 11 px / 550` |
| 颜色 | 白色文字；图标 `#E9FAFF` |
| 背景 | `linear-gradient(135deg,rgba(25,151,211,.96),rgba(92,202,244,.94))` |
| 圆角 | `10 px` |
| 阴影 | `0 10px 24px rgba(21,119,168,.28)`，附带 `1 px rgba(255,255,255,.32)` 内高光 |

| 辅助信息 | `aria-live="polite"` 只在拖动开始和目标位置变化时更新，不连续朗读指针坐标 |

| 尺寸 | 主线 `4 × 104 px`；占轨道宽度约 `0.24%`、轨道高度约 `89.7%` |
| 颜色 | `#19AEEB`，双层发光 `0 0 8 px` 与 `0 0 18 px` |
| 端点 | 上下各 `8 × 8 px` 圆点，占主线高度约 `7.7%` |
| 标签 | 主线上方 `移动到第 04 位`，约 `88 × 22 px`；字体 `9 px / 13 px / 700` |
| 状态 | 有效目标、原位无变化、全部镜头已选无目标、导出中禁用 |
| 原位反馈 | 插入线隐藏，徽标辅助文案改为 `保持原位置` |
| 动画 | 目标槽切换使用 `100 ms` 透明度过渡；不做弹跳或缩放 |

### 3.4 GroupDraggingShotSegment

| 字段 | 规格 |
| --- | --- |
| 类型 | Selected Timeline Segment State |
| 位置 | 所有参与成组移动的 `ShotSegment` |
| 尺寸 | 保持原镜头宽高，不在拖动期间重排 DOM 或压缩宽度 |
| 外观 | 透明度 `62%`；内描边 `2 px rgba(53,180,236,.78)`；蓝色阴影增强 |
| 主拖动镜头 | 额外使用 `3 px rgba(255,255,255,.82)` 外环，表明指针来源 |
| 其他已选镜头 | 保留勾选框，但选择控件在拖动期间不接收点击 |
| 未选镜头 | 透明度与位置保持不变，作为插入目标参照 |
| 鼠标 | 所有参与镜头握把显示 `grabbing`；其他镜头保持默认 |
| 交互 | 拖动期间不修改项目数据；`pointerup` 后一次性提交最终顺序 |

### 3.5 ShotDragGrip 组模式

| 字段 | 规格 |
| --- | --- |
| 类型 | Drag Handle / Keyboard Group Move Control |
| 位置 | 沿用 V12 多选模式下镜头左上角位置 |
| 尺寸 | 沿用 `24 × 24 px` 视觉区与至少 `30 × 30 px` 可点击区 |
| 普通拖动 | 未进入多选或只有 1 个镜头时，继续使用 V11 单镜头重排 |
| 成组拖动 | 多选模式且当前握把属于选择集合、已选数量至少 2 时，移动整个集合 |
| 未选镜头拖动 | 先将该镜头加入现有选择，再将更新后的选择集合成组移动 |
| 全选 | 全部镜头已选时握把禁用，`title="全部镜头已选，无可移动目标"` |
| 键盘 | `Alt+Shift+← / →` 将已选组向前或向后移动一个有效插入槽；`Alt+← / →` 保留单镜头微调 |
| 辅助信息 | `aria-label="成组拖动 3 个镜头；Alt+Shift+方向键可调整"` |

## 4. 成组排序与数据规则

### 4.1 组成员与相对顺序

- 组成员以稳定镜头 ID 判断，顺序始终来自当前 `shots` 时间线，而不是用户勾选的先后顺序。
- 非连续选择首次移动后收拢为连续组，同时保留成员之间的原相对顺序。
- 例：`[A, B, C, D, E]` 选择 `[B, D]` 并移动到 `E` 前，结果为 `[A, C, B, D, E]`。
- 组中镜头的场景、剧集、图片、台词、时长、动效和转场字段不变；只改变全局成片顺序。
- 所有镜头已选时没有有效目标，操作为 no-op，不记录历史。

### 4.2 插入槽计算

- 操作开始时先从原时间线移除组成员，得到只包含未选镜头的 `remainingShots`。
- 有效插入槽为 `remainingShots.length + 1` 个：轨道开头、未选镜头之间和轨道末尾。
- 指针越过未选镜头中点时切换目标槽；被选镜头自身不参与目标槽计算。
- `pointerup` 时按目标槽将整组插入 `remainingShots`；结果签名与原顺序一致时视为 no-op。
- 轨道水平滚动时使用容器坐标和实际卡片边界计算，不假设固定镜头宽度。

### 4.3 键盘移动

- `Alt+Shift+←` 将组移动到前一个有效槽，`Alt+Shift+→` 移动到后一个有效槽。
- 键盘移动每次只跨过一个未选镜头；到达首尾后不再移动，也不产生空历史。
- 操作完成后主镜头保持不变，焦点返回原握把，选择集合不清空。

### 4.4 字幕、音轨与播放头

- 使用一次旧时间线和一次最终新时间线调用现有 `synchronizeTimelineDependents`，不得逐镜头循环同步。
- 有来源字幕随所属镜头移动；无来源字幕沿用最大重叠镜头规则；文本、样式和 ID 不变。
- 角色配音随镜头重建；SFX 保留所属镜头内相对偏移；BGM 保持绝对起点。
- 播放头保持主镜头内的相对进度，并移动到主镜头新起点对应位置。
- 成组移动不改变镜头时长，因此成片总时长保持不变。

### 4.5 历史、恢复与项目保存

- 一次完整成组拖动只记录一步，历史文案为 `成组移动 3 个镜头 → 第 04 位`。
- 撤销、重做同时恢复镜头顺序、字幕时间、SFX 起点和播放头；选择集合继续保留。
- 项目继续使用 `shots` 数组顺序保存，不新增 `.manju` 字段或格式版本。
- 自动恢复点只在有效拖动提交后建立；拖动预览和 no-op 不触发保存。
- 不新增依赖、IPC、权限或 Provider；真实 AI 接口继续保持预留未接入。

### 4.6 取消与异常

- `Escape`、`pointercancel`、窗口失焦或捕获丢失时取消本次组拖动，恢复原顺序且不记录历史。
- 拖动过程中镜头集合发生外部变化时，以操作开始快照为基准验证 ID；失效成员跳过，少于 2 个有效成员时降级为单镜头移动。
- 导出开始后禁用新拖动；已开始的拖动必须先取消，再创建导出快照。

## 6. 状态、响应式与设计规范

- 颜色：保持 `#F4FBFF → #D7F1FF → #74CAFF` 页面渐变；组拖动主色 `#19AEEB`；徽标使用 `#1997D3 → #5CCAF4`。
- 字体：Windows 系统无衬线；徽标主文案 `10 px / 750`，辅助文案与目标标签 `8–9 px / 550–700`。
- 间距：沿用 `4 / 8 / 12 / 16 px`；新增浮层不改变镜头带布局。
- 圆角：徽标 `10 px`、目标标签 `7 px`、镜头和握把沿用现有值。
- loading：无异步加载；拖动过程不保存，提交在 pointer up 同步完成。
- empty：少于 2 个已选镜头时不出现组徽标，沿用单镜头排序。
- error：有效成员不足时安全降级；无法计算目标槽时取消并显示本地通知。
- disabled：导出中、所有镜头全选或只有 1 个镜头时禁用无意义的组移动。
- selected：勾选框与批量描边继续存在；组拖动态增加透明度和统一阴影，不只靠颜色表达。
- pressed：拖动握把切换为 `grabbing`，镜头不缩放到影响插入槽计算。
- permission denied：不新增文件或系统权限。
- 长文本：徽标只使用镜头数量与总时长，不显示镜头标题；超过 99 个显示 `99+`。
- 小屏：小于 `1180 px` 时轨道继续水平滚动；徽标限制在可视容器内，插入槽仍按实际卡片中点计算。
- 暗色/高对比：当前不新增暗色主题；强制颜色模式下使用可见实线插入标记与文字标签。
- 横竖屏：编辑器仍以 Windows 桌面横向为基准；导出比例不影响排序逻辑。
- 减少动态：取消淡入位移与阴影过渡，直接显示状态。

## 7. React 与服务层实现映射

| 设计区域 | 建议映射 | 责任边界 |
| --- | --- | --- |
| 组拖动预览态 | 扩展 `FinalPage` 的 `shotInteraction` | 只保存成员 ID、原顺序、目标槽、指针位置和主镜头，不提前写项目数据 |
| 组成员归一化 | `shotTimelineEditService.js` 纯函数 | 按当前时间线顺序过滤稳定 ID、去重并清理失效成员 |
| 成组插入算法 | 新增 `reorderShotGroupByInsertion` | 输入原镜头、成员 ID 和剩余轨道槽位，输出最终顺序；无 DOM 依赖 |
| 键盘组移动 | 新增 `moveShotGroupByStep` | 每次跨过一个未选镜头，保持成员相对顺序 |
| 下游同步 | 复用 `synchronizeTimelineDependents` 与 `remapTimelinePlayhead` | 最终顺序只同步一次，避免累计误差 |
| 历史 | 复用 `timelineHistoryService` 的 `shotTimeline` 快照 | 一次组拖动记录一步，撤销重做覆盖整个组 |
| 保存与恢复 | 现有项目 Repository 与恢复点接口 | 继续以 `shots` 数组顺序保存，不保存拖动浮层或选择手势 |
| 样式 | `App.css` 的 `.production-timeline` 区域 | 新增组徽标、组拖动态和目标位置标签，不改变全局主题 |

## 10. 不确定项与推测值

- 现有运行截图没有组拖动徽标和有效槽标签，其尺寸来自 V11 插入线与 V12 批量工具条的视觉比例推测。
- 非连续选择在首次拖动后收拢为连续组，这是桌面批量排序中最可预测的结果；不会创建持久分组。
- 全选镜头整体移动不会改变顺序，因此设计为禁用状态而不是产生空历史。
- V13 不加入批量删除；删除仍保留在分镜页的明确单镜头流程中。
- 本设计默认继续使用简体中文、天蓝渐变毛玻璃和当前单层时间线，不重新设计其他页面。
